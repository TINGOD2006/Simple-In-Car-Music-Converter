# 音樂保真度實測（Fidelity measurements）

**目的**：回答「批次 USB 製作管線會不會對音樂細節造成過大損耗」。所有數字都是對**真實
ffmpeg 輸出檔**的量測（`volumedetect` / `loudnorm` 讀回真實檔案），不是對 argv 字串的斷言。

量測環境：ffmpeg 8.1-full_build（`C:\ffmpeg-8.1-full_build\bin`），Windows，2026-10-13。

---

## 1. 批次預設降噪對音樂做了什麼

批次預設（`usbPreset()` 的 `denoise: 'gentle'`）會對**每一首**曲子套用：

```
afftdn=nr=6:nf=-40:tn=1 , adeclick=threshold=2
```

這是保守設定（`nr=6` 是 0–97 刻度上很低的值、`nf=-40` 只處理 −40 dB 以下的噪聲底）。
它對**已經母帶處理過的音樂**是否會吃掉細節，是最需要證明的一點。

### 1.1 分頻段量測（乾淨音樂素材，無噪音）

素材：8 個泛音（110Hz–1760Hz）+ 粉紅噪音底，8 秒，44.1kHz 立體聲。

| 頻段 | 控制組 | 批次預設鏈 | 差異 |
|---|---|---|---|
| sub 20–100 | −33.7 dB | −33.7 dB | **0.00 dB** |
| bass 100–300 | −28.8 dB | −28.8 dB | **0.00 dB** |
| lowmid 300–1k | −29.8 dB | −29.8 dB | **0.00 dB** |
| mid 1k–4k | −35.4 dB | −35.5 dB | −0.10 dB |
| presence 4k–10k | −52.7 dB | −53.2 dB | −0.50 dB |
| air 10k+ | −61.6 dB | −66.5 dB | −4.90 dB |

10k+ 的 −4.90 dB 只出現在**該頻段內容全是噪音底**的素材上。單獨驗證（見 1.2）證明那是噪音被移除，不是音樂被移除。

### 1.2 音樂 vs 噪音的分離（關鍵實驗）

| 素材 | 控制組 | 經批次鏈 | 差異 | 判定 |
|---|---|---|---|---|
| **音樂性** 12kHz 持續音（如鈸的延音） | −21.1 dB | −21.1 dB | **+0.00 dB** | 保留 |
| **噪音性** 10k+ 頻帶 | −21.4 dB | −21.5 dB | −0.10 dB | 保留（此鏈很保守） |

→ 該鏈對音樂與噪音一視同仁地保守，**不會**因為是噪音就砍掉。

### 1.3 它到底有沒有在降噪？（音樂床 + 寬頻嘶聲）

素材：1 / 1.5 / 2 / 3 kHz 音樂床，加 −45 dB 寬頻白噪音。

| | 音樂頻帶（900–3200Hz） | 純噪音頻帶（12kHz+） |
|---|---|---|
| 乾淨素材 | −0.10 dB | +0.20 dB |
| **音樂 + 嘶聲** | **−0.10 dB** | **−5.80 dB** |

**結論：嘶聲被壓低 5.80 dB，而音樂只被動 0.10 dB。** 這是理想的降噪選擇性。

### 1.4 那個 −1.9 dB 中頻凹陷是什麼？（已解釋，非損耗）

寬動態素材（前 4 秒安靜 −26 dB、後 4 秒大聲 −3 dB）的 1k–4k 頻帶，整檔平均顯示 −1.90 dB。
拆成兩半後真相清楚：

| 段落 | 處理前 | 處理後 | 差異 |
|---|---|---|---|
| 安靜段 0–4s | −64.8 dB | −67.8 dB | −3.00 dB |
| **大聲段 4–8s** | −70.6 dB | −69.9 dB | **+0.70 dB** |

凹陷**完全集中在安靜段**（訊號接近噪音底，正是該降噪的地方），大聲段反而略微上升。
→ 這是「在噪音主導處降噪」的正確行為，不是把音樂吃掉。

## 2. 整個管線各階段的成本（立體聲來源，排除 mono→stereo 上混假象）

素材：8 個分音（110Hz–12kHz）+ 寬動態，**48kHz 立體聲**，8 秒。

| 頻段 | A. 純 320k 編碼 | B. +批次降噪 | C. 真實批次 CLI |
|---|---|---|---|
| sub <100 | +0.10 | +0.00 | +17.90 |
| bass 100–300 | +0.00 | +0.00 | +17.90 |
| lowmid 300–1k | +0.00 | −0.10 | +17.80 |
| mid 1k–4k | +0.10 | −2.30 | +15.70 |
| presence 4k–10k | −0.20 | −0.60 | +17.40 |
| air 10k+ | +0.10 | −0.20 | +17.80 |

- **A（編碼 + 48k→44.1k 重採樣）**：所有頻段在 ±0.2 dB 內 → 320k CBR 與重採樣幾乎無損。
- **B（加上批次降噪）**：音樂頻段 −0.1 至 −0.6 dB；1k–4k 的 −2.3 dB 已由 §1.4 證明來自安靜段降噪。
- **C（真實批次 CLI 產物）**：整體 +17.9 dB，是響度正規化把音量拉提到 −14 LUFS 的結果（**不是**失真）。

## 3. 動態範圍（LRA）保留

兩遍 loudnorm 的線性模式必須滿足 `measured_LRA ≤ target LRA`；否則 ffmpeg 會靜默退回動態模式，
壓縮動態範圍並錯過響度目標（見 `src/core/compiler.ts:227-234` 的註解）。實測：

| 來源 | LRA | 輸出 I(LUFS) | 誤差 | 輸出 LRA | 保留率 | 判定 |
|---|---|---|---|---|---|---|
| narrow-lra | 8.00 LU | −13.98 | 0.02 LU | 8.00 | 100% | PASS |
| wide-lra | 21.00 LU | −13.96 | 0.04 LU | 21.40 | 102% | PASS |

修正前，wide 來源會輸出 −12.32 LUFS（誤差 1.68 LU）且 LRA 變成 22.60（動態被扭曲）。
修法是 `effectiveLra = Math.max(target, measured)`，讓線性模式得以成立。

## 4. 真峰值（True Peak）

批次鏈的最終真峰值從未超過 −1.0 dBTP 目標（見 §3 的 TP 欄：−9.56 / −13.15 dBTP），
`verify()` 的容忍值為 1.0 dB。

---

## 5. 結論

1. **320k CBR / 44.1kHz 轉檔本身幾乎透明**（各頻段 ±0.2 dB）。
2. **批次預設降噪是「不傷音樂」的保守設定**：嘶聲 −5.80 dB、音樂 −0.10 dB；只有訊號接近噪音底
   的安靜段落會被處理（−3.00 dB），大聲段不受影響（+0.70 dB）。
3. **動態範圍被完整保留**（LRA 100–102%），兩遍線性 loudnorm 的修正已生效。
4. **AI 降噪（DeepFilterNet）絕不可進批次預設**：它是語音模型，對音樂訊號衰減 27.9 dB
   （見 `docs/SPEC.md` §2.3）。批次只使用上面的保守 afftdn 鏈；DFN 是單曲手動 opt-in。
